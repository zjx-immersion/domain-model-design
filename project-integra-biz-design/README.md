## 🎯 设计理念

### 业务视角优先
```
传统导航：按功能模块分类（产品、需求、项目、Sprint...）
新导航：按业务视角分类（产品中心、项目中心、团队工作台）

优势：
✅ 符合用户工作流程
✅ 减少页面跳转
✅ 提升信息查找效率
```

### 一页式管理
```
问题：信息分散在多个页面，需要多次点击和记忆
解决：每个核心视角提供一页总览

产品中心首页 → 产品资产全景（一页看全所有产品）
项目中心首页 → 项目全景图（一页看全所有项目）
团队工作台首页 → 团队工作全景（一页看全当前迭代）
```

### 上下文保持
```
跨视角跳转时，保持关键信息：

产品详情 → 点击"在项目中的应用" → 项目详情（自动筛选该产品）
项目详情 → 点击"产品版本" → 产品详情（自动定位到该版本）
需求详情 → 点击"负责团队" → 团队待办（自动筛选该需求）
```

## 💡 使用建议

### 产品经理工作流

```
1. 每日工作开始 → 打开"产品资产全景"
   - 查看产品健康度卡片
   - 关注黄色/红色预警产品
   
2. 版本规划时 → 在产品树中选中产品
   - 查看右侧详情面板的版本Roadmap
   - 点击版本查看包含的特性和模块
   - 查看"在项目中的应用状态"，评估资源需求
   
3. 需求评审时 → 从特性跳转到需求
   - 保持产品上下文
   - 快速定位到相关需求
   
4. 跨项目协调 → 使用"产品-项目状态矩阵"
   - 识别同一产品在多个项目中的版本差异
   - 发现资源冲突
```

### 项目经理工作流

```
1. 每日站会前 → 打开"项目全景图"
   - 查看车型项目看板，关注风险项目
   - 在时间轴上查看当前Sprint进度
   
2. 周报编写时 → 使用项目对比功能
   - 勾选2-4个项目进行对比
   - 导出对比报告
   
3. 里程碑评审时 → 在时间轴上点击里程碑
   - 查看关联的项目、PI、Sprint
   - 分析延期风险
   - 制定应对计划
   
4. 资源协调时 → 查看依赖关系图
   - 识别关键路径
   - 优化资源分配
```
